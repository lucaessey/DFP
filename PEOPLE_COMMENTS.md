# People Comments and Producer

## Current design: Firebase-only manual approval

On September 29 the owner cancelled Cloudflare setup and approved manual review. The game uses only the existing Firebase project **DFP game / dfp-game-e2926**, on **Spark**, with no billing changes, Cloud Functions, service-account key or moderation API.

- Producer comments are delivered to the private Producer inbox.
- Every Everyone comment is stored privately as Awaiting Review. Only the verified producer can approve publication.
- Ordinary players cannot publish, approve, edit existing submissions, change an audience, read private/pending text or grant themselves privileges.
- The owner may approve/reject pending comments, mark private notes read and hide public comments. Reports are private flags for the owner; reporting does not hide or publish a comment.

The earlier `worker/` implementation and historical test files are retained but inactive. Automatic language checks and Cloudflare activation instructions no longer apply.

## Configuration and access

Firebase public app identifiers remain in `src/people/config.js`. No administrative credential belongs in the browser. Anonymous sign-in, Google, and Email/Password with Email link must remain enabled. The authorized production domain is `lucaessey.github.io`; email return URL is `https://lucaessey.github.io/DFP/`.

Rules authorize Producer only when Firebase verifies `lucaessey@gmail.com` through Google or email-link/password. A typed address or local flag is insufficient. The client refreshes owner tokens and performs a protected read before showing the app. Google sign-in avoids email delivery delays; a real owner login still requires the account holder. Existing email send limits and error handling remain.

## Storage and privacy

All data remains under `/peopleComments`. `public`, `private`, `pending`, and `ownerPublic` keep their existing `all` and exact-star projections. Public rows contain only ID, text, rating and timestamp. Canonical records stay under `internal/records`; only the verified owner may read an individual canonical record, and bulk canonical reads remain denied.

Anonymous clients may atomically create their own canonical record, matching private/pending projections, receipt and quota update. Firebase rules enforce 1–500 characters, integer rating 1–5, audience/acknowledgement, immutable fields, initial private state, matching projections, timestamps and quotas. The checked-in rules are generated by `node scripts/generate-comment-rules.mjs`.

`receipts/<uid>/<requestId>` exposes only that author's opaque ID, payload fingerprint, initial status and accepted timestamp, never comment text. UID plus request ID determines the canonical ID. Confirmed receipts make failed-request and reload retries idempotent. Owner actions use sequential revisions and action IDs; a delayed approval cannot undo a hide. Producer audience cannot change to Everyone, even through a direct owner request.

Rules enforce a 30-second cooldown, six submissions/hour and 20/day per UID. These limits do not prevent someone creating many anonymous accounts. No IPs are collected. The Spark plan's own finite quotas remain in effect.

Private feedback is held in memory and cleared on sign-out, offline/backgrounding or view closure. Firebase requests use no-store and are not cached by the PWA. Drafts stay locally with a shared-device warning; game saves and purchases are unaffected.

## Local verification

Use the existing Node and Java 21 runtimes. Start the Auth/Database emulators with `npm run comments:emulators`. They use **demo-dfp-comments**, never production.

Build the test game with `npm run build -- --mode test-comments --outDir artifacts/people-manual/build`, then serve it with `npx vite preview --configLoader native --outDir artifacts/people-manual/build --host 127.0.0.1 --port 4188 --strictPort`. No local comment API is required.

Run:

```text
npm test
npm run test:comments:rules
npm run test:comments:browser
npm run test:comments:google
npm run test:comments:auth
npm run build:pages
npm run spec:comments
```

The rules suite resets only the disposable emulator database. Browser tests use isolated profiles and test-only game saves. Screenshots and reports are under `artifacts/people-manual/`. `test:comments:repair` aliases the current manual-flow suite; the former external-backend test files describe historical behavior.
